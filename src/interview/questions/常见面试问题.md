# 常见的面试问题
### 浏览器的缓存机制
1. 缓存位置
* Memory Cache：内存缓存，速度快但生命周期短（随标签页关闭释放）。
* Disk Cache：磁盘缓存，持久化存储大文件（如CSS、JS、图片）。
* Service Worker Cache：通过Service Worker控制的缓存，支持离线访问。
* Push Cache：HTTP/2推送资源的临时缓存（会话级别）。
2. 缓存的策略
```typescript
// 缓存行为由HTTP头部控制
// 1. 强缓存(无需服务器验证)
var header = {
    "Expires": "Wed, 09 Jul 2014 02:00:00 GMT", // 制定资源的过期时间
    "Cache-Contro": "max-age=86400", // 资源剩余时间
    "Cache-Contro": "no-cache", // 强制协商缓存
    "Cache-Contro": "no-store",// 强制不缓存
    // ...
}
// 2. 协商缓存(需服务器验证)
/*
* 当强缓存失效时，浏览器向服务器验证资源是否修改
* Last-Modified & If-Modified-Since：
*   1.服务器返回Last-Modified（最后修改时间）。
*   2.浏览器下次请求携带If-Modified-Since，若资源未修改，服务器返回304 Not Modified
* ETag & If-None-Match： 
*   1.服务器返回ETag（资源唯一标识符）。
*   2.浏览器下次请求携带If-None-Match，若资源未修改，服务器返回304 Not Modified
* */
```
3. 缓存流程
* 首次请求：无缓存，直接下载资源，按响应头存入缓存
* 再次请求
*      1:检查强缓存(Cache-Control/Expires),若有效则直接使用缓存(状态码200)
*      2.检查协商缓存(Last-Modified/ETag),若有效则直接使用缓存(状态码304)
*      3.资源未修改则返回304,使用缓存；已修改则返回新资源(状态码200)
###### script标签的deffer和async属性
1. 默认情况(<script/>): 浏览器遇到js时会停止解析Dom，等待js执行完毕，再继续解析。
2. defer(<script defer />):浏览器遇到js时,会异步加载js(不会阻塞HTML解析), 加载完成后立即执行
3. async(<script async />):HTML解（并行下载脚本）→ 脚本下载完 → 立即执行（可能中断解析）
###### 什么是重排和重绘?有什么影响
1. 重排: 浏览器重新计算元素的几何属性(位置、尺寸),页面布局发生变化。
2. 重绘: 重新绘制元素的视觉样式(颜色\背景等),但布局不变。
影响:

       会产生性能问题:
         1.重排的开销远大于重绘，因为它会导致整个或部分页面重新计算布局
         2.频繁的重排/重绘会导致页面卡顿，影响用户体验（尤其是在动画、滚动等场景）。 

### 浏览器的解析与渲染流程
* 解析HTML → 构建DOM树
* 解析CSS → 构建CSSOM树
* 合并DOM和CSSOM → 生成渲染树（Render Tree）
* 重排(计算元素位置和大小)和重绘(填充像素到屏幕) → 绘制页面
* 合成（Composite） → GPU渲染最终页面
```text
  HTML → DOM Tree  →
                      → Render Tree → Layout → Paint → Composite
  CSS  → CSSOM Tree →
  *  JavaScript（可能阻塞DOM/CSSOM）
```

### TCP/IP协议
###### IP协议:负责将数据包从源设备发送到目标设备，基于IP地址进行寻址和路由
特点：
1. 无连接:不预先建立连接，直接发送数据包。
2. 不可靠:不保证数据包一定到达，也不保证顺序正确（依赖TCP纠错）。
3. 版本: IPv4(32位地址，面临枯竭)、IPv6(128位地址，解决IPv4不足)

###### TCP协议:在IP协议基础上提供可靠、面向连接的数据传输。
特点：
1.  三次握手（建立连接）
 ```text
 客户端 → SYN → 服务端  
 服务端 → SYN+ACK → 客户端  
 客户端 → ACK → 服务端  
```
2. 可靠传输：通过确认应答（ACK）、超时重传、流量控制（滑动窗口）确保数据不丢失、不重复。
3. 适用于：网页（HTTP）、邮件（SMTP）、文件传输（FTP）等需要可靠性的场景
###### UDP协议：提供无连接、不可靠但高效的数据传输。
1. 无握手，直接发送数据。
2. 不保证数据到达，但延迟低。
3. 适用于：视频通话（Zoom）、在线游戏、DNS查询等实时性要求高的场景。
```markdown

| TCP/IP四层    | 功能                          | 典型协议            |
|---------------|-----------------------------|---------------------|
| 应用层        | 提供网络服务(如网页、邮件)      | HTTP、FTP、SMTP、DNS |
| 传输层        | 管理端到端通信(可靠/不可靠传输) | TCP、UDP            |
| 网络层        | 负责寻址和路由(跨网络传输)      | IP、ICMP、ARP        |
| 网络接口层    | 处理物理网络连接              | Ethernet、Wi-Fi      |

```

### TCP三次握手\四次挥手具体过程
1. 三次握手：

       1.客户端->服务端: 发送SYN包给服务端 2.服务端->客户端: 收到后返回SYN+ACK包,并ACK确认  3.客户端->客户端ACK确认。
2. 四次挥手：
   
       1. 客户端->服务端: 发送FIN包给服务端 2. 服务端->客户端: 收到后返回ACK包 3. 客户端->服务端: 发送FIN包给服务端 4. 服务端->客户端: 收到后返回ACK包

不管是建立连接还是断开服务，都是由客户端发起，服务端接收，然后返回给客户端。
